## Purpose

Single `load_model` dispatch for the daemon. Owns `LoadedModel` (arch state as `Option<Box<dyn ArchModel>>` + one `parallel: ModelParallelKind` topology owner), the object-safe `Carrier` trait and `REGISTRY` in [`src/carriers.rs`](src/carriers.rs) / [`src/lib.rs`](src/lib.rs) (impls stay in `carriers.rs` because `Carrier::load` returns `LoadedModel` and arch crates must not depend on the loader), `ModelSource::from_path` source × carrier routing (HFQ vs `SafetensorsSource` dir, `UNCLAIMED_ARCH_ID` sentinel), the CAP-001 admission boundary (`admit_path` / `load_admitted`), `model_parallel` / `parallel_capability` policy modules, `batch_staging`, and `spec_build` RAII glues. Arch-agnostic callers destructure only via `as_arch_model{,_mut}`.

## Gotchas

- `load_model` requires exactly one matching carrier (0 → error; 2 → ambiguous) — add a carrier only after reserving its `arch_id` in `docs/architecture-ids.md`.
- Per-arch load bodies now live in the arch crates as `load_<arch>_bundle(src, ctx)`; `carriers.rs` is the thin registry that calls them — do not pull weight/config parsing back into the loader.
- `LoadedModel.ep` holds expert-parallel rank state separately from `state`; EP staging reclaims completed ranks on failure but a mid-constructor failure can leak that rank's partial allocs.
