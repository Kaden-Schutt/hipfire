## PIVOT (2026-07-06) — the executor is `execute_steps(mesh, gpus)`, and it is the ONLY spine

### What the master merge revealed
The 519-commit master merge (`5b95cbd3`) invalidated the plan's executor assumption. A 4-agent read-only sweep of the post-merge worktree established the ground truth:

- Master shipped **`dense_forward`** (`crates/hipfire-runtime/src/arch_spec.rs:131`, commit `2a41f98f`): a shared dense-decode driver that builds a transient `Vec<Step>` per layer and feeds **`execute_steps(gpu: &mut Gpu, ctx, steps)`** (`crates/hipfire-dispatch/src/pipeline/steps.rs:600`). **llama** (`llama.rs:3460`) and **qwen2** (`qwen2.rs:1927`) now route through it. The merge **reverted `3a3c60e5`** (which had wired qwen2 → `run_layer_program_mesh`).
- There are now **two independent decode spines with no shared code** — parallel op vocabularies:

  | Spine | Op IR | Driver | Arches | Call sites |
  |---|---|---|---|---|
  | **A — dense** | `Step` | `dense_forward` → `execute_steps(&mut Gpu)` | llama, qwen2 (+ qwen35 & cohere2moe call `execute_steps` directly) | **63** |
  | **B — superop** | `SuperOp` | `run_layer_program[_mesh]` via `ForwardBindings` | deepseek4, minimax, lfm2moe | **~4** (9 w/ `_ep`/`_mesh`) |

- The device-mesh work built its whole executor (`run_layer_program_mesh`, `superop.rs:457`) on **Spine B**. Master made **Spine A** the dense default. `execute_steps` is the true chokepoint — even Spine B's prefill and `run_layer_program` bottom out in it. **The mesh belongs at `execute_steps`.**

### The new thesis (supersedes §1)
> **Exactly ONE executor: `execute_steps(mesh: &DeviceMesh, gpus: &mut Gpus, ctx, steps)`.** Replace the `gpu: &mut Gpu` parameter with `(mesh, gpus)` and execute the fan-out transparently inside. The `Step` IR is the single lowering for **all arches and all axes**; the `SuperOp`/`ForwardBindings`/`run_layer_program*` substrate is **retired for parallelism** and its one novel piece (the EP-MoE all-reduce lifecycle) is migrated into a `Step`.

**Decisions locked (2026-07-06):**
- **Grand-unify** — MoE/EP folds into `execute_steps` too. The "live" EP path (`run_layer_program_mesh` EP branch serving deepseek4/minimax) is **this branch's own phase-2 feature work**, not a production contract — free to refactor/retire. One spine, no exceptions.

> **CLARIFICATION (2026-07-07, bjoern) — "one spine / `Step::Moe`" means DECOMPOSE, not a monolithic op.** The grand-unify's intent is to **compose MoE/DeltaNet out of SEPARATE fine-grained Steps** (MoE = `Route` → grouped expert GEMM → `SiluMul` → grouped-down + combine; DeltaNet = projection Gemvs + `Step::Recurrent`/`Conv`), splitting WHAT (ops+operands) from HOW/WHERE (placement via the manifest, collectives via the executor) — exactly as `Step::Attend` already does for attention. ## Context

hipfire's three multi-GPU strategies are scattered, per-arch, and non-transparent:

- **PP (pipeline)** is hand-coded in **one** arch (qwen35): decode `forward_scratch_layers_multi` and prefill `forward_prefill_batch_multi` hand-loop layers and `gpus.boundary_copy` the residual at each layer-band boundary. (Verified serve-wired end-to-end this session: `HIPFIRE_EMULATE_GPUS=2 HIPFIRE_PP=2` via the Bun CLI → coherent qwen3.5-4b output.)
- **EP (expert-parallel)** has a generic *decode* executor — `hipfire_runtime::ep::run_layer_program_ep` drives a `LayerProgram` across ranks, special-casing `SuperOpKind::Moe → all-reduce`. deepseek4 + minimax + qwen35-MoE use it. But **prefill EP** all-reduce is hand-inlined per arch (`forward_prefill_batch_ep`), *not* through `ep.rs`.
- **TP (tensor-parallel)** sharding math exists (`ShardConfig`), but drives **no live forward**; today `tp>1` in the daemon *means EP*. Real row/column TP is greenfield.
- **Loading is per-arch + imperative**: sharded weight upload is bespoke inherent methods, *not* on the `Architecture` trait; routing is **tp/pp-param-driven** (`tp>1 → load_model_ep`, `pp>1 → load_model_pp`) with `arch_id` as *internal guards* (`load_model_ep` accepts only 9/10; `load_model_pp` only 5/6 at daemon.rs:4843). Four near-duplicate `load_model_*` end in a `LoadedModel{…}` literal (**52 fields / 36 `Option`**). PP state (`pp_gpus`) and EP state (`EpState`/`EpArch`, only `Ds4|Minimax`) are **separate ownership universes** in the daemon *example binary* — the documented EP-rehome blocker.
- **State placement is imperative + format-exploded**: ~15 `KvCache::*_multi` ctors funnel into 3 hand loops; DeltaNet keeps its own `la_to_device` sidecar (LA-compact index ≠ KvCache global index); lfm2moe conv-state has *no* multi path.

**Goal:** any model implementing `ForwardBindings` + declaring its `LayerProgram` (and a weight/state manifest) gets PP/TP/EP **for free** — placement, sharding, and cross-device sync driven entirely by the engine. **Ambition: maximal transparency-by-construction** — the model's *forward path* is structurally unable to observe parallelism (device count, rank, global-shard dims, layer index, or collective calls never enter forward-time arch code; wrong parallelism code fails to compile). Reached via a **phased, no-regression roadmap**; each phase is its own coherence/byte-exact-gated PR.

**Two tiers of transparency (name them explicitly — do not conflate).**
- **Tier 1 — device/dim transparency (Phases 0–5, shippable):** the `DeviceMesh` drives compute *and* placement, so the arch never observes device count, rank, or global sharded dims. Weights/state are sliced to `(stage,tp_rank)` before the arch receives them; the arch keeps resolving operands from its own (now-local) fields. This is real and deletes the PP/EP/loader duplication.
- **Tier 2 — layout/operand transparency (Phase 6, *optional* stretch — likely not worth the full migration):** the executor would hand the arch each operand *per-op by slot* (the `superop.rs` slot-binding seam), so the arch couldn't inspect its local layout. Greenfield assessment: this chases GSPMD-grade structural unobservability, which is a *property of having an array compiler* — hipfire deliberately has none (hand HIP kernels, `KernelKey` frozen at lower time). Over a **curated** arch set, "arch reads its own pre-sliced local fields" (Tier 1) is a defensible **permanent** stopping point; a slot migration across all 5 arches buys little. **Downgraded from "the finish line" to an open question.** Non-blocking regardless — Phase 2/3 must never depend on it (the slot seam is verifiably empty: `ScratchSlot` has zero constructions today).

**Tier-1 boundary — head-axis sharding makes FusedQKV *and* DeltaNet transparent (they are NOT `Custom`).** Both shard along the **head axis**, not row/col, and the math already exists in `tp_shard` as *dead scaffolding* — this design is its first consumer:
- **`FusedQKV{q_heads,kv_heads,head_dim}` + a declarative fused-block layout descriptor** (where the Q|K|V|gate boundaries sit — DeltaNet `q|k|v`+separate `wz`, FullAttn `q|gate`, vanilla `q|k|v`): the engine splits the fused tensor at the boundaries, shards each sub-block by its head group via `q_head_range`/`kv_head_range`. Layout is *data*, not code.
- **`HeadSharded` for DeltaNet `w_alpha/w_beta/wz`**: each rank owns a subset of linear-attention heads (`dn_value_head_range`); its recurrent S-matrix/conv state co-shards by head (a `StateEntry` head-sharding); per-head recurrence is independent; cross-head mix is `wo` row-shard + all-reduce (standard TP). Requires wiring the currently-dropped `s_ef_residual` normalization (qwen35.rs:1091) for correctness.

Both are **load-time architectural declaration** (head structure), not forward-time parallelism observation → still Tier-1-transparent. **Greenfield caveat:** the `tp_shard` head-range math has never driven a forward — this is real Phase-5 work, but declarative, not an escape hatch. So `Replicate/Column/Row/FusedQKV/HeadSharded/Vocab` are all generic; **only `ExpertSharded`** carries an irreducibly arch-specific convention (MoE packed-blob + pointer-table + zeroed-dummy) — a rich policy with a per-arch descriptor. `Custom{shard_fn}` shrinks to "genuinely bespoke, no known example in the current fleet."

The substrate is ~60% built: `LayerProgram`/`SuperOpKind`/`ForwardBindings` exist (`crates/hipfire-dispatch/src/pipeline/superop.rs`) and **5 of 8 arches drive their (default-on) lowered single-GPU forward through it** (qwen35, qwen2, deepseek4, minimax, lfm2moe). This design finishes and generalizes that seam.

## North-star architecture (target end-state)

### 0a. Placement is a **`DeviceMesh` tree of typed `Dimension` nodes** — PP / TP / EP compose, and topologies may be ragged
**Primary model = a named-axis mesh** (industry-converged: JAX `Mesh(('pp','tp','ep'))`, PyTorch `DeviceMesh`, Megatron process-groups): a device's **coordinate** is an index tuple over the present axes `{Pp, Tp, Ep}`, and its **collective group along an axis** = all devices sharing the *other* coordinates. This already expresses **coexisting TP and EP at different group sizes** — a MoE model reduces its expert op over the `Ep` group and its attention over the `Tp` group, exactly how Megatron/JAX do it (`group_along(kind, coord)` + `CollectiveHint{kind}` is the mechanism; *named axes*, not nesting, are what's required).

**The mesh is stored as a `Dimension` tree solely to allow raggedness** — a named-axis mesh is strictly *rectangular* (uniform `Tp`/`Ep` size across all `Pp` stages), which **heterogeneous / mixed-arch hardware can't live within**. The dev fleet is deliberately mixed (hipx = gfx1151 + gfx1010; contributor rigs pair APU+dGPU or 7900XTX+5700XT), so **different shard-group size per stage** is a real need — TP-2 on the strong card's stage, TP-1 on the weak card's — which a rectangular mesh forbids and a tree (each `Pp` node carries its own sub-tree) allows. Ragged *pipeline band sizes* already exist (`init_layers`/`HIPFIRE_PP_LAYERS`); the tree extends the same raggedness to `Tp`/`Ep`, and `init_vram_weighted` (multi_gpu.rs:147 stub) chooses the shape from per-device capability. So: **named-axis semantics primary; tree representation only for raggedness** — the common rectangular case is `DeviceMesh::rect([{Pp,n},{Tp,n},{Ep,n}])` and never touches the tree.

**Mixed-arch meshes need per-arch *lowering*, not per-device caps.** `ArchCaps` + `FeatureFlags` are **already per-device** — they live on `Gpu` (dispatch.rs:332-334), each built from that device's detected arch (`FeatureFlags::from_env(&gpu.arch)`); nothing to restructure. The real gap: `KernelKey`s are resolved and **frozen at lower time** (superop.rs:14) via arch-conditional selection (WMMA on gfx1151 vs not on gfx1010), so a single `LoweredForward` can't run on two arches. On a mixed-arch mesh, **`LoweredForward` becomes keyed by arch** — lower once per distinct arch present, and each mesh cell runs the lowering matching its `arch_caps`. Supporting items (Phase 5b): promote the mixed-arch preflight from a default *refusal* (multi_gpu.rs:731-750, `HIPFIRE_ALLOW_MIXED_ARCH` override) to a first-class path; audit `FeatureFlags` for any kernel gate that doesn't check the *executing device's* `arch_caps`.

**Discipline (so the tree isn't the N1 over-build):** the **rectangular case is a one-line convenience constructor** `DeviceMesh::rect([{Pp,n},{Tp,n},{Ep,n}])`, so the common path never touches raggedness; the tree is contained in `hipfire-hardware` and `group_along(kind, coord) -> &[usize]` returns a flat device-id slice, so **the executor + collective signatures are identical whether the mesh is rectangular or ragged** — adopting the tree ripples nowhere above hardware. Degenerate cases: single-GPU = one leaf; PP-only = root with N leaves; EP-only = today's `init_tp`. No `EpPp` special mode; the `pp>1 && tp>1` refusal lifts in Phase 5b once the multi-axis loader/dispatch exists.

Collectives become **group-scoped and level-named**: `AllReduce{kind: Tp|Ep, …}` reduces over the device's group *along that `Dimension`*; `BandXfer` copies between adjacent `Pp` siblings. This needs a real (small) change, NOT free: today `all_reduce_sum_f32[_peer]` **reject** a buffer subset (`buffers.len() != devices.len()`) and index `devices`/`peer_ar_tmp`/streams *positionally over all devices* (multi_gpu.rs:492/604). Add a `group: &[usize]` (global device ids) param to both, indexing through `group[k]`, in **Phase 0's mechanical move** — current call sites pass `group = 0..n`, keeping every 1D case byte-identical; then Phase 5b is pure wiring, not a signature break. The RCCL path additionally needs per-group communicators (`ncclCommSplit`), deferred to 5b.

The daemon `pp>1 && tp>1` refusal (daemon.rs:1861) is **lifted only in Phase 5b**, once the 2D loader + dispatch exist — Phase 0's mesh relabel *keeps* the refusal (lifting it earlier would silently route a 2×2 request into 1×N EP, dropping `pp`).

**Discipline (avoid the N1 over-generalization bounce):** adopt the tree as the *data model* early (a relabel of `layer_to_device`/`band_starts` + the `group_along(kind, coord)` accessor in `hipfire-hardware`, `rect(...)` constructor for the common case — near-zero cost, single-axis behavior unchanged), but only *exercise* a multi-axis / ragged forward in the late composition phase. Real consumers: **hiptrx (4× gfx1201)** → 2×2 PP×TP; **hipx (gfx1151 + gfx1010)** → ragged (asymmetric stage sizes); `HIPFIRE_EMULATE_GPUS` fakes a 2×2 mesh on one card for dev — not speculative.

### 0b. Extract `hipfire-hardware` so ONE executor can live in ONE crate
The naive split (single-GPU `run_layer_program` in dispatch, parallel executor in runtime) concedes the "one executor" premise — two `run_*` in two crates — because the EP/PP arms need `Gpus`/collectives, which sit in runtime, and dispatch→runtime would cycle. **Fix the crate graph instead of the executor:** extract `multi_gpu.rs` (`Gpus` + `boundary_copy`/`all_reduce`/`enable_peer_all`/`init_*`/device-resolution) into a new **leaf crate `hipfire-hardware`** (deps: `hip-bridge` + `rdna-compute` only — RCCL is already a leaf in `hip-bridge`). The *only* coupling to break is 5 `crate::config::get()` reads in `multi_gpu.rs` (`tp_use_rccl`, `devices`, `emulate_gpus`, `allow_mixed_arch`, `uniform_vram_tolerance_gb`) — pass them in as an explicit `DeviceResolveOpts` param, which also removes a hidden global from the hardware layer. Then **`hipfire-dispatch` depends on `hipfire-hardware`** and hosts the whole executor.

### 1. Exactly ONE executor — `run_layer_program(mesh, gpus, lowered, bindings)`
> **SUPERSEDED by `## PIVOT` (2026-07-06):** the one executor is `execute_steps(mesh, gpus)` on the `Step` IR, not `run_layer_program` on `SuperOp`. The 1×1-identity and collective-hint reasoning below is correct and carries over verbatim to `execute_steps`; only the IR/function name changes. Read for the mesh-degeneration argument, not the entry point.

There is **no `ParallelMode` enum and no `run_layer_program_parallel`**. Single-GPU is a **1×1 `DeviceMesh`**: a singleton TP-group (all-reduce over one buffer = identity) and one stage (BandXfer never fires), so the *same* executor runs it with all collective hints `None` — a per-op branch that is not taken, byte-identical to today's single-GPU output. PP is N×1, EP/TP is 1×N, stacked is N×M — all the *same* function; the mesh is the only thing that changes. The executor lives in **hipfire-dispatch** (enabled by the Phase-0 `hipfire-hardware` extraction), is generic over `B: ForwardBindings`, and takes `&mut Gpus` + the mesh from hardware. **The arch is transparent to device count** (Tier 1) — it declares a `LayerProgram` + implements `ForwardBindings`, and calls one executor; whether it runs on 1 GPU or a 2×2 mesh is never visible to it. The 1×1 arm **must leave `devices[0]`'s stream state untouched** — it never calls the EP-only `ensure_rank_streams` (which flips `active_stream None→Some` and silently switches the hot-path memset sync→async, per CLAUDE.md); only the ≥1×N arms touch streams. (`Gpus::single` — multi_gpu.rs:156 — already models the 1-device set with no RCCL/peer state; it consumes the `Gpu` by value, so the daemon owns its `Gpu` inside a `Gpus` for the process lifetime — a mechanical Phase-0b refactor, zero runtime cost.)

Sync lives at two scopes because it genuinely does in the code:
- **Per-op** `CollectiveHint::AllReduce{kind: Tp|Ep, rows*dim}` — `Ep` for `Moe` ops, `Tp` for row-sharded `o_proj`/dense. Executor issues `gpus.all_reduce_sum_f32[_peer](group_along(kind, coord), …)`. **Derived from the `ShardPolicy`, not hand-injected** (greenfield: single source of truth). A `RowShard`/`ExpertSharded` weight *mechanically implies* an all-reduce on its consuming op — a **transformer-template mini-partitioner** in generic lowering reads the manifest policy and emits the hint, so sharding is declared **once** (in the manifest) and the collective can't be forgotten (kills the silent-wrong-reduce class). This runs as a post-pass over each arch's `*_lower_program` output (where `KernelKey`s are frozen), needing no per-arch collective code.
- **Per-layer-boundary** `BandXfer{src_dev,dst_dev}` on `LoweredForward.band_xfer: Vec<Option<BandXfer>>` indexed by layer — PP. Executed by the **outer driver** *between* per-layer `run_layer_program` calls (PP sync fires between layers; a per-op hint cannot see the previous layer's device). A 1×1 or 1×N mesh has all-`None` band_xfer and all-`None` op hints → hot path byte-identical.

### 2. IR carries `n_rows` — prefill and decode unified (and it must be an *arbitrary token set*, not contiguous prefill)
The current IR is **decode-only** (per-token; `superop.rs` has no batch dim; `ep.rs` reduces a scalar `residual_dim`). Prefill is 3 bespoke drivers (single-GPU batched, PP `forward_prefill_batch_multi` with N-row band handoff, EP `forward_prefill_batch_ep` with hand-inlined `n*dim` all-reduce). Generalize the executor to carry `n_rows`: `BandXfer` copies `n_rows*dim`, `AllReduce` reduces `n_rows*dim`. This deletes all three hand-rolled loops, not one.
- **Bake-in decision (cheap now, expensive later):** define `n_rows` as an **arbitrary position-indexed token set**, NOT prefill-contiguous, and verify the EP/TP all-reduce + BandXfer never assume row contiguity. The DFlash/DDTree spec-decode stack (a Phase-7 track) is **tree-structured** (draft + tree-mask verify + per-node acceptance); if Phase 2 bakes `n_rows`=contiguous batch, the "drafter as mesh coordinate" track inherits an IR that can't express cross-rank tree-verify and pays twice. This is the single Phase-0–5 decision that could foreclose a Phase-7 track — reserve against it in Phase 1a/2.

### 3. Collectives owned by the executor, not the arch
**Tier 1 (now):** the EP pattern already ships — `ForwardBindings::run_moe_ep` writes a partial into an arch-owned tensor and `ep_add_into_residual` reads it back post-reduce; the executor issues the collective. Generalizing the `CollectiveHint` path keeps this shape: the arch op-body produces the partial in its own scratch, the executor reduces it. No arch op-body *calls* a collective — enforced by return-variant convention + review.
**Tier 2 (Phase 6):** `dispatch_super_op` returns `OpOutput::{Complete, Partial(ScratchSlot)}` and the executor resolves `ForwardBindings::resolve_scratch(slot) -> &GpuTensor` — but `ScratchSlot` has **zero constructions today** and `resolve_scratch` doesn't exist (the slot-binding seam is empty TODO, superop.rs:244-247), so this is the same Tier-2 migration as layout-transparency, not a Phase-1 mechanism. `ScratchSlot` is a `Copy` enum (`Activation(u32)|State(u32)|Cache(u32)`, superop.rs:55) → no lifetime conflict when it does land. **The compile-time guarantee** (arch physically can't `use …::all_reduce`) rests on two things: (a) the `hipfire-hardware` leaf crate from **Phase 0** — arch crates never list it as a direct dep, so its collective symbols are unnameable there; and (b) **rehoming the per-arch driver loops** (`forward_ep`, `forward_scratch_layers_multi`, …) up into runtime so they, not the arch crates, hold `&mut Gpus` (Phase 6). Until (b) lands, arch crates still reach collectives via their existing `hipfire-runtime` dep, so the interim guarantee is "executor owns collectives, op-bodies don't call them" (≈90% of the value) enforced by return-variant + review; after Phase 6, wrong code fails to compile.

### 4. Loading is mesh-driven too — placement = manifest (what) × mesh (where)
**The loader takes the same `DeviceMesh` as the executor** (§1), so weights and state land on the correct `(stage, tp_rank)` locations transparently — the arch declares *what it needs* and never names a device, rank, or device count on the load side any more than on the forward side. Symmetry: the executor projects the `LayerProgram` onto the mesh for *compute*; `fulfill_manifest` projects the manifest onto the mesh for *placement*.

`Architecture` gains `fn weight_manifest(cfg) -> Vec<WeightEntry>` and `fn state_manifest(cfg) -> Vec<StateEntry>` (pure CPU, device-count-agnostic — **derived per load, never serialized into `.hfq`, so there is no on-disk back-compat surface**: manifest versioning is defined out of existence, do not add serialization):
- `WeightEntry{name,logical_shape,dtype,policy}`, `ShardPolicy { Replicate | ColumnShard{axis} | RowShard{axis} | ExpertSharded{n_experts,assign} | FusedQKV{q_heads,kv_heads,head_dim,layout} | HeadSharded{n_heads,head_dim} | Tied{source} | Pin{Embed|Output} | VocabShard{axis} | Custom{shard_fn} }`. `FusedQKV`/`HeadSharded` shard the **head axis** via `tp_shard`'s `q_head_range`/`kv_head_range`/`dn_value_head_range` (see Tier-1 boundary above); `FusedQKV.layout` is the declarative Q|K|V|gate block descriptor.
- `StateEntry{ kind: Kv{quant} | Recurrent | Conv, layer_scope }` — the state sibling; same mesh projection, collapsing the ~15 `KvCache::*_multi` ctors and the DeltaNet `la_to_device` sidecar into one keyed `StateStore` (global-layer vs LA-compact index reconciled **in the engine**).

**`fulfill_manifest(manifest, hfq, mesh)` is one loop** driven by the mesh accessors — `mesh.stage_for_layer(L)` (the `Pp` coordinate owning a layer) and `mesh.group_along(Tp|Ep, coord)` (the shard group for a sharded weight along its axis):
- **Where (PP axis):** a layer's weights/state go to the stage owning that layer; `Pin{Embed}` → stage 0, `Pin{Output}`/`VocabShard` → last stage (the Megatron output convention, now a mesh projection not a hardcode).
- **How, within the owning stage (TP axis):** `Replicate` → full tensor to every rank in the TP-group; `ColumnShard/RowShard{axis}` → `tp_size` slices along axis, slice `r` → rank `r`; `ExpertSharded` → experts distributed across the group (deepseek4 zeroed-dummy trick, **once, in the engine**); `FusedQKV` → `tp_shard`'s GQA-aware `q_head_range`/`kv_head_range`; `VocabShard` → the (currently nonexistent) TP logit cursor.
- **Transactional (partial-failure safe):** `fulfill_manifest` uploads real-dtype tensors, so a rank can OOM mid-loop (the Phase-1 shape-only dry-run uses *zeroed* descriptors and won't catch VRAM exhaustion). On any per-cell alloc failure, **free all already-populated cells and return `Err((coord, WeightEntry))`** — never leave a half-loaded mesh.
- **VocabShard changes the sampling path** (specify it, don't leave implicit): `generate_ep` gathers logits on rank 0 and samples there today, assuming a **replicated** lm_head. With a vocab-split lm_head, the shards must be **all-gathered to one designated rank**, after which the existing single-rank sampler / EOS filter / loop-guard / `sampler_overrides` blocked-token logic runs **unchanged**. (Distributed argmax+renorm is the alternative but needlessly complicates greedy+sampling+EOS; prefer gather.)
- Each tensor is **sliced to its `(stage,tp_rank)` before the arch receives it** → global dims never enter arch code.
- **The store is a load-side *placement* container, keyed by `(logical_name, mesh_coord)`** — it populates the arch's existing per-device weight/state fields (the same fields `load_weights_multi` fills today), replacing the god-struct's placement bookkeeping. Its value should be a **handle enum (`Resident(GpuTensor)` | future `Paged(WeightId)`)** so the deferred `WeightPager` × mesh axis slots in additively without re-keying. It does **NOT** feed the forward by slot: the executor still reads arch fields (Tier 1). Slot-keyed operand resolution `(layer,slot,mesh_coord)` is **Tier 2 / Phase 6 only** — adopting it now would invert the dependency onto the unbuilt `superop.rs` slot-binding seam (`OpBinding.weights/scratch` are empty TODO today).
- `StateStore` must be **keyed by global layer index**, not a compacted `Vec` — that is what defines the DeltaNet `la_to_device` sidecar out of existence (LA-vs-full-attn knowledge lives in *manifest construction*, which the arch owns via `config.layer_types`; `stage_for_layer(global)` needs none of it). Note the pre-existing multi-path `s_ef_residual` drop (qwen35.rs:1091) is a real single-vs-multi numerical divergence — bake it into the Phase-1b PP oracle's expectations.
- The **same manifest** fulfills on 1×1 (everything to the one device), N×1 (banded by stage, no slicing), 1×N (one stage, sliced across ranks), and N×M (both) — zero arch change across all four.
- **`WeightPager` × mesh is explicitly deferred/out-of-scope** (not a drop-in): the pager is inert single-device scaffolding (`WeightId` has no device axis; `free_gpu_multi`/`shard_moe_experts` currently *assert* `pager.is_none()`). UMA lowers its priority; revisit as its own item if >VRAM-across-mesh is needed.

### 5. The proper-abstraction endgame: ONE runtime object + an arch vtable
This is what makes the design *engine-level* at the daemon layer, not just the executor. **Scope reality:** `EpState`/`EpArch`/`LoadedModel` (52 fields / 36 `Option`) live in the daemon **example binary** (`examples/daemon.rs`), not a library — so Phase 3's real, least-mechanical, riskiest content is **hoisting this machinery into the runtime lib** as `ModelParallel` + `Box<dyn ArchDispatch>` (the "Phase 3 fallback: god-struct stays as compat" escape is example-local). Collapse the god-struct + every `arch_id==` guard into exactly:
`LoadedModel = { tokenizer, mesh: DeviceMesh, parallel: ModelParallel, arch: Box<dyn ArchDispatch> }`.
- `ModelParallel{ gpus, mesh, weights: WeightStore, state: StateStore }` absorbs `EpState`/`EpArch` + `pp_*` — **one** reset/checkpoint/abort site (the documented EP-rehome blocker for qwen35-hybrid, and the #462 state-bleed surface).
- `ArchDispatch` is the trait object the daemon calls instead of matching `arch_id`: `weight_manifest`/`state_manifest`/`lower_program`/`make_bindings` + sampler/eos/prompt overrides. The manifest declaration is its natural attachment point. This is what removes the `arch_id==` ladders scattered through the daemon and is the linchpin of daemon-side transparency.

### 6. Safety-by-construction (woven through phases)
- **Collective-manifest diff** `validate_rank_programs` (renamed from `validate_ep_manifest` — it now validates any mesh's per-rank sequence, TP/PP too): compare only the `SuperOpKind` sequence per rank (NOT `KernelKey`, which legitimately differs under TP); disagreement → refuse at init. CPU, CI-testable.
- **Shape-only dry run** at load (zeroed descriptors, no-op collectives) → TP shard-math shape bugs fail at load, not token-1 page fault.
- **Transactional `fulfill_manifest`** (see §4) — free-and-`Err` on any mid-load OOM; never a half-loaded mesh.
- **NaN-poison** the PP residual source after `wait_boundary` (gated `HIPFIRE_PP_NAN_POISON`/`debug_assertions`).
- **`(device_id, request_epoch)` stamp** in `ModelState`, checked atop advancing-state ops — covers **both `Recurrent` (DeltaNet) and `Conv` (lfm2moe)** — turning the #462 request-bleed class into an immediate panic.
- **Determinism invariant (protects the byte-exact gates):** all sampling RNG is drawn on **one designated rank after the logit gather** — no per-rank forward RNG. Corollary for the Phase-1b PP oracle: pin a fixed seed + assert identical draw count/order across the `=0`/`=1` arms (the DeltaNet `s_ef_residual`-drop **stochastic** path, qwen35.rs:1093, is otherwise not byte-reproducible — the oracle compares multi-vs-multi, where both arms drop EF and match; single-vs-multi divergence is separately accepted, then removed when Phase 5 wires `s_ef_residual`).
- **Observability:** `HIPFIRE_MESH_DUMP=1` / `mesh.describe()` at load prints the resolved tree + coord→(dev,rank) + per-layer stage/group placement — a wrong mesh should be a readable dump, not a page fault.

### Invariants
- **Single-thread HIP**: the executor stays single-threaded (device-switch + one async stream per rank; FIFO stream overlap). It must **never** spawn an OS thread per rank. The deferred async-overlap optimization must honor this.

## Deferred / rejected
- Async collective/compute overlap (double-buffered partials) — perf, single-thread-safe, after correctness.
- **Rejected: adaptive/emergent placement** (starvation-cut PP, stigmergy TP-steal, pheromone expert migration) — incompatible with byte-exact/coherence determinism. A *static* profile-derived PP band-cut is the only survivor, optional.
- JIT weight streaming (>VRAM) — orthogonal; UMA lowers priority.
- Training/backward placement reuse — out of inference scope.
