# H-Neurons in hipfire — identification pipeline (arXiv 2512.01797)

Status: IMPLEMENTED (identification). Reproduces the hallucination-associated
neuron (H-Neuron) identification method — per-neuron CETT contribution capture +
a sparse L1 logistic probe — natively in hipfire, driven through the daemon.
Intervention (per-neuron gain sweep) is a follow-up.
Date: 2026-07-01

## Method (what we reproduce)

For each response token, neuron `j` in a dense FFN contributes `act_j · W_down[:,j]`
to the residual. Its **CETT** score is

```
CETT(layer, j) = |act_j| · ‖W_down[:,j]‖ / (‖down_proj_output‖ + 1e-8)
```

Per sample we mean-aggregate CETT over the response tokens, yielding a
`[n_layers × intermediate]` feature. An L1-regularized logistic regression on
`{feature → hallucinated?}` selects a sparse set of neurons; the positive-weight
neurons are the H-Neurons. This matches the reference `extract_activations.py`
(`weight_norms = torch.norm(down_proj.weight, dim=0)`) + `classifier.py`.

## Implemented pieces

1. **Model-independent core** — `crates/hipfire-hneurons/src/lib.rs` (landed in
   034d53ab): `cett()`, `CettFeatures` (per-layer mean accumulator), and
   `L1Logreg` (proximal-gradient ISTA with feature standardization,
   `h_neurons()` / `nonzero()`).
2. **CETT capture session + FFN tap** — `crates/hipfire-hneurons/src/capture.rs`:
   a process-global `ACTIVE`-gated session mirroring the steer hook.
   `maybe_capture_ffn(gpu, ffn_hidden, down_out, layer, batch_start, n)` runs
   right after `down_proj`, folding each response token's CETT into the running
   per-layer feature. One-line placement per arch.
3. **Forward tap** — wired into `hipfire_runtime::llama::prefill_forward` (the
   generic `weight_gemm` whole-sequence prefill), which materializes both the
   `down_proj` input and output as standalone tensors (the quant-fused batched
   path folds the output into the residual, so it can't tap the denominator).
   No-op unless a capture session is active; the daemon serving path
   (`forward_prefill_batch`) is untouched.
4. **Column norms** — `scripts/hneurons_colnorms.py` (tooling): reads the source
   fp16 `down_proj.weight` and writes a compact binary
   (`[u32 n_layers][u32 intermediate][f32 …]`, LE) the daemon loads once.
5. **Daemon ops** — `cett_load_colnorms { path }` and
   `cett_capture { system, user, response }` in `hipfire-daemon`, with protocol
   types + `DaemonEngine::{cett_load_colnorms, cett_capture}` client methods.
   `cett_capture` jinja-frames the prompt, appends the response tokens, prefills
   the tapped forward, and returns the `[n_layers][intermediate]` feature.
6. **Orchestrator** — `hipfire-hneurons-probe`
   (`crates/hipfire-steer-harness/src/bin/hneurons_probe.rs`): loads a labeled
   TriviaQA split, captures every sample's feature via the daemon, fits
   `L1Logreg`, reports train/test accuracy + the H-Neuron set.

## How to run

```
# 1. column norms from the source fp16 checkpoint
python3 scripts/hneurons_colnorms.py <hf_model_dir> colnorms.bin

# 2. capture + probe (spawns a daemon, loads the model)
hipfire-hneurons-probe \
  --daemon target/debug/hipfire-daemon \
  --model ~/.hipfire/models/Llama-3.1-8B-Instruct.q8f16.hfq \
  --colnorms colnorms.bin \
  --data-dir third_party/H-Neurons/data/examples \
  --data-prefix Llama33_TriviaQA --limit 200
```

Labels come from the reference `qids.json` (`t` = correct → y=0, `f` =
hallucinated → y=1); `answer_tokens_*.jsonl` supply `(question, response)`.

## Result (Llama-3.1-8B-Instruct q8f16, gfx1103)

`--data-prefix Llama33_TriviaQA --limit 200` (200 train / 200 test, balanced
100 correct / 100 hallucinated per split):

```
features:       458752 (32 layers x 14336)
train accuracy: 1.0000
test accuracy:  0.6750
nonzero weights:1796
H-Neurons (positive-weight): 909
```

Test accuracy is well above the 0.50 balanced-chance floor, so the mean-response
CETT features carry a linearly-separable hallucination signal even in the
cross-model setting below. Train 1.0 is the expected overfit of a 458k-feature /
200-sample fit; the L1 prox keeps only 1796 of 458752 weights nonzero. The paper
reports higher in-domain accuracy with self-generated answers — the gap is
consistent with the cross-model caveat.

## Caveats / honest scope

- **Cross-model responses.** The vendored `Llama33_TriviaQA` responses were
  generated by Llama-3.3, not the resident Llama-3.1-8B. Feeding them through 8B
  probes whether 8B's FFN encodes a factual-correctness signal for arbitrary
  answer text — a method demo, **not** the paper's self-generation protocol. The
  on-paper claim needs answers generated by the model under test (a
  daemon-`generate` + TriviaQA-gold-match labeling step; see follow-ups).
- **Small slice.** `--limit` caps the sample count for tractability; the capture
  path is sequential (one prefill per sample) and unoptimized. Not the paper's
  full-corpus scale.

## Follow-ups

- Self-generated labeling: daemon-`generate` answers for the target model, label
  by TriviaQA gold substring match, then capture — the on-paper protocol.
- GPU-side CETT reduction: the tap currently downloads the full-sequence FFN
  tensors per layer per sample. A fused on-GPU per-token CETT reduction removes
  the host bounce.
- Intervention: a per-neuron gain mode (`act_j ← α·act_j` at the FFN tap) +
  compliance sweep, mirroring the reference Figure 3.
- Multi-arch: the tap is one line per arch; gemma3/qwen2 have analogous MLP
  intermediates. MoE arches route per-token (per-expert H-Neurons — separate
  design).
