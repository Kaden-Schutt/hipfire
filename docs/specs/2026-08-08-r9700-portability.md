# R9700 (gfx1201) portability of SP1–SP7

- **Date:** 2026-08-08
- **Status:** analysis; nothing in this programme has ever run on gfx1201

Every number in this programme was measured on Strix Halo (gfx1151). The
deployment target is an R9700 (gfx1201), which differs in two ways that matter:
it is a **discrete 32 GB card, not unified memory**, and it takes **different
kernel dispatches**.

## Should work, with evidence

| Area | Why |
|---|---|
| Multi-slot attention | On gfx1201 `q8_flash_prefill_wmma_eligible` is false (`!has_wmma_w32_gfx12()`), so the WMMA tile path never fires and the bare descriptor path runs. That exact dispatch outcome was verified numerically on this box via `HIPFIRE_FLASH_PREFILL=0`: golden gate **10/10 at 0.000×**. |
| Kernel resources | `kernel_resource_gate.sh` fingerprints VGPR/scratch/occupancy for 6 kernels on **gfx1151 AND gfx1201**, and is bitwise identical to beta. |
| Batched lm_head | `GEMV_HFQ4G256_XBATCH_SRC` carries no arch define — it is generic. The hand-tuned single-vector lm_head kernel is gfx1151-only, so gfx1201 already runs the generic one. |
| Flash crossover | gfx1200/gfx1201 keep their existing 4096. The 2048 measured here was applied to gfx1151 **only**. |
| Memory budget | `preflight_alloc` and `AdmissionController` are already sized against `R9700_VRAM_BYTES` (32 GiB), which is the target, not this box. |
| Prefix cache, swap, serve | Pure host logic plus device copies; no arch-specific kernels. |

## Will differ, and by how much is unknown

- **All performance numbers.** 110 tok/s at 4 slots, 2.03–2.24× serve
  concurrency, the 136 GB/s MoE figure and the 214 GB/s streaming reference are
  gfx1151 measurements. gfx1201 has different bandwidth, different CU count and
  takes the non-WMMA attention path, so the shape should carry but the
  magnitudes will not.
- **Host-tier KV swap latency.** This is the one that could invert a design
  decision. Strix Halo is unified memory, so VRAM↔host is nearly free here; on
  the R9700 the same copy crosses PCIe. The spec already records host-tier
  numbers as provisional. Disk-tier numbers roughly transfer — NVMe is NVMe.
  This is the same hazard that invalidated the expert-spill idea.
- **The 27B at 4 × 128K.** 33.25 GB against a 32 GB card, so admission must cap
  context near 96K. On this 128 GB box that ceiling is never reached, so the
  cap has never actually been exercised.

## Untested, and only R9700 access closes it

Nothing here has executed a single kernel on gfx1201. What exists is
compile-time fingerprinting plus a numerically-equivalent dispatch forced on
gfx1151. Those are good evidence that it is *correct*; they say nothing about
whether it is *fast*, and nothing about the memory system at all.

First things to run on an R9700, in order:

1. `test_forward_slots_golden` — correctness of the real dispatch.
2. `scripts/serve_concurrency_gate.sh` — end-to-end concurrency.
3. `demo_multislot_generate` at 1–4 slots — the throughput curve.
4. `test_swap_roundtrip` / `test_swap_equivalence` with timings — the PCIe
   question, which is the only one that could change the design.
