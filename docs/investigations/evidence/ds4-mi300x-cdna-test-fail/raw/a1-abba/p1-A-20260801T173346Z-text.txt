### 1. The Primacy of Prompt Bytes Over "Text"

The measurement contract is defined by **exact byte sequences**, not human-readable text. The reason is simple: tokenizers are deterministic functions of bytes. A single trailing newline, a UTF-8 normalization difference, or a BOM changes the token sequence. The contract therefore mandates:

- **A fixed source corpus** (e.g., a multi-paragraph technical document, not random words or repeated loops).
- **A derived 2040-token prefix** of that corpus, verified by a tokenizer round-trip: `encode(decode(encode(corero))` must yield the exact same 2040 IDs.
- **No trailing newline** in the fixture file.
- **MD5 and SHA-256** of the exact bytes of the fixture file as ledger fields.
- **A separate `--tokens-out` file** containing the 2040 token IDs as little-endian u32 values, generated by the same runtime tokenizer.

This ensures that every measurement uses the exact same token sequence, regardless of platform, editor, or toolchain. The "text" is irrelevant; the bytes are the contract.
