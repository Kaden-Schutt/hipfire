## Phase 0 · Metadata gate — no weights, ~2 minutes

This is the whole decision point. Per the readiness analysis, an empty key-set
diff means the existing loader serves 3.8 unchanged.

```bash
# config.json ONLY — a few KB. Do not pull weights yet.
python3 - <<'PY'
from huggingface_hub import hf_hub_download
import json, subprocess
new = json.load(open(hf_hub_download('Qwen/Qwen3.8-27B', 'config.json')))
old = json.load(open(hf_hub_download('Qwen/Qwen3.6-27B', 'config.json')))
def text(c): return c.get('text_config', c)
n, o = text(new), text(old)
print('model_type (top):', new.get('model_type'), '| nested:', n.get('model_type'))
print('added  :', sorted(set(n) - set(o)))
print('removed:', sorted(set(o) - set(n)))
for k in ('num_hidden_layers','hidden_size','intermediate_size','vocab_size',
          'head_dim','num_attention_heads','num_key_value_heads','rope_theta',
          'tie_word_embeddings','layer_types','num_experts','num_experts_per_tok',
          'linear_num_value_heads','mtp_num_hidden_layers'):
    if n.get(k) != o.get(k):
        print(f'CHANGED {k}: 3.6={o.get(k)!r} -> 3.8={n.get(k)!r}')
lt = n.get('layer_types')
if lt: print('layer_types value set:', sorted(set(lt)))
PY
```

**Stop conditions.** Any of these halts the day-1 push and becomes a code task
before quantizing:

1. **`layer_types` contains a value other than `full_attention` /
   `linear_attention`.** Highest-consequence unknown: unknown values collapse to
   `FullAttention` (`qwen35.rs:518-528`) with no error, which loads the wrong
   kernel family and surfaces as a missing-tensor panic *or* as silently wrong
   output. Check this first.
2. **`model_type` contains `3_8` / `3.8`.** Falls through to arch 0 (llama) with
   only a warning. Fix is three string literals — `auto_arch_id`,
   `derive_arch_id`, and the `hfq.rs` provenance list — plus `--arch-id 5`
   (dense) or `6` (MoE) to unblock immediately.
3. **MoE at Max fan-out** (512 experts / top-10) would meet the EP/TP refusals
   (`tp_size != 4`, `layer_types` length checks, `head_dim % 32`). Dense 27B is
   unaffected.

Also capture the card's own settings now, because Phase 3 asserts against them:

```bash
python3 - <<'PY'
from huggingface_hub import hf_hub_download
import json
for f in ('generation_config.json', 'tokenizer_config.json'):
    try:
        d = json.load(open(hf_hub_download('Qwen/Qwen3.8-27B', f)))
        print(f'--- {f}'); print(json.dumps(d, indent=1)[:1200])
    except Exception as e:
        print(f'--- {f}: {type(e).__name__}')
PY
# And read the card prose for a Best Practices / Usage section:
#   read https://huggingface.co/Qwen/Qwen3.8-27B
```

Record verbatim: `temperature`, `top_p`, `top_k`, `min_p`, `presence_penalty`,
`repetition_penalty`, max context, and any thinking-mode guidance. These are the
Phase 3 oracle.

## Phase 1 · Acquire + quantize

Only after Phase 0 is clean.

```bash
hf download Qwen/Qwen3.8-27B --local-dir ~/models/Qwen3.8-27B   # ~54 GB bf16

cargo build --release -p hipfire-quantize
./target/release/hipfire-quantize ~/models/Qwen3.8-27B \
    --format mq4 --out ~/.hipfire/models/qwen3.8-27b.mq4
```

Notes:

- **MQ4 is the day-1 trunk.** MQ6 is the quality tier if wanted; MQ3 is
  production on gfx11/gfx12 but is a second pass, not day 1. **MQ2 is refused by
  default and stays refused.**
- **No AWQ on day 1.** AWQ needs an imatrix; no third party will have published
  one for 3.8 yet, and hipfire's native HFIM collector lives unmerged on
  `origin/feat/hfim-native-imatrix` and requires an F32 oracle (111 GB class).
  Ship plain MQ4 first; AWQ is the follow-up on rented CDNA3.
- Confirm the stamped arch id in the load log before proceeding.

## Phase 2 · Load smoke, per arch

Cheapest real signal. Run on each device in the matrix, fresh process.

```bash
./target/release/examples/run ~/.hipfire/models/qwen3.8-27b.mq4 \
    "Write a Python function to reverse a linked list"
```

Pass = coherent decoded text, no missing-tensor panic, plausible tok/s. **Read
the output.** Per `CLAUDE.md`, numbers never prove coherence; a single-token
attractor passes every statistical gate as a fake win.

On the local 17 GB gfx1201, expect to cap context; use hiptrx or hipx gfx1151 for
long-ctx work.

## Phase 3 · Parent-model-card conformance

This is the step that makes "day-1 support" mean something more than "it loads."

1. **Registry entry mirrors the card.** Add `qwen3.8:27b` to
   `registry/models.json` with `recommended_settings` transcribed from Phase 0 —
   not guessed, not copied from 3.6. Mirror 3.6's `sampling_profiles` structure
   (`general` / `coding` / `instruct`) only where the card actually distinguishes
   them; absent guidance means the profile is deliberately omitted rather than
   invented (the Glimmer entry sets this precedent, and
   `bundled_muse_glimmer_matches_the_model_card_sampling_contract` enforces it).
2. **Assert it in a test**, following that same Glimmer precedent, so a later
   edit cannot silently drift the shipped defaults away from the card.
3. **Verify the engine honors it**: `hipfire config qwen3.8:27b show` must report
   the card's values, and a generation run must not override them. Watch for
   `min_p > 0`, which disqualifies both speculative routes on the Glimmer path —
   check whether the same gate applies here before claiming spec-decode support.
4. **Context length**: confirm the card's max position embeddings against what we
   allocate, and record the ctx at which 24 GB / 32 GB actually OOMs rather than
   quoting the card's theoretical max.

## Phase 5 · Publish

1. Upload to **`hipfire-models/qwen3.8-27b`** — no `hipfire-` prefix, format in
   the filename, per the 2026-08-14 org consolidation.
2. Card must state: requires hipfire (not GGUF), the quant recipe, measured-vs-
   unmeasured quality honestly, and `base_model: Qwen/Qwen3.8-27B`.
3. `python3 scripts/registry_gen.py && python3 scripts/registry_gen.py --check`
   — the generator validates size and sha256 against HF and fails on >0.25 size
   drift.
4. **Merge beta → master.** Clients fetch the registry from
   `raw.githubusercontent.com/warpfront/hipfire/master/registry/v1.json`; the
   bundled copy is only a fallback. Until beta lands on master, `hipfire pull
   qwen3.8:27b` does not resolve for anyone — and neither does `muse-glimmer`,
   which is live on HF and on beta but not yet on master.

## Phase 6 · Performance — last, never first

Only after Phase 4 passes. Per
[`docs/methodology/perf-benchmarking.md`](../methodology/perf-benchmarking.md)
and `AGENTS.md`:

- ≥3 **fresh-process** runs; within-session A/B drifts 10–15% from DPM/thermal.
- **Byte-identical prompts** from `benchmarks/prompts/*.txt`. One newline can
  swing τ 17%. Record the prompt md5 and the binary md5 or the result is
  unreproducible.
- Canonical fixture: `benchmarks/prompts/merge_sort_thinking_off.txt`
  (md5 `253c7ac50857fe6d0e10fb0d2c5e35c0`).
- A **tight stddev on a spec-decode bench is suspicious, not reassuring.**
- New numbers go to a dated record in `docs/perf-checkpoints/` (append-only;
  never modify an existing one) — not into `docs/BENCHMARKS.md`, which is
  admission-gated.

## Follow-ups, explicitly out of day-1 scope

- **DFlash draft for 3.8** — no drafter exists day 1. Without one, spec decode is
  unavailable; do not report AR numbers as if speculative.
- **MTP** — if 3.8 ships an MTP head, it needs `mode = "mtp"` selected or the
  head loads and the speculative loop silently never runs (gen=0, no error
  envelope). `mtp_num_hidden_layers: 1` matched 3.6.
- **AWQ / GPTQ** — needs an imatrix or Hessian; see the Glimmer oracle runbook
  for the rented-CDNA3 path that produces both from one F32 oracle.
- **MQ3 / MQ6 tiers** — second pass.

2. Artifact quantized, arch id confirmed from the load log.
3. Coherent decoded output read on **gfx1100, gfx1151, and gfx1201**.
4. Registry entry transcribed from the card, asserted by a test.
5. `serve_harness.py battery` + `chain` pass, decoded text eyeballed.
6. Uploaded, `registry_gen --check` clean, beta merged to master so `hipfire pull
