# gfx1201 — Radeon AI PRO R9700, RDNA4 / Navi48

Living lever map for gfx1201. See [README.md](README.md) for the method + instrument→lever table.

## Silicon
64 CU, 4 Shader Engines, 2× SIMD32/CU, wave32, max 32 waves/CU, 64KB LDS, ~2350+ MHz.
32GB GDDR6, **~640 GB/s**. L2 + ~64MB MALL. **256-byte cacheline.** Native WMMA matrix cores. **FP8/FP4 capable.**

## Cache behavior: RESIDENT (the good case)
Census shows **L2-hit ~64-78%** on the decode kernels (qkvza 78%, gate_up 64%, moe_down 76%) — reads mostly
hit low-latency cache. This is WHY gfx1201 keeps pace with gfx1100 despite 40% less bandwidth: gfx1100 pays
DRAM latency, gfx1201 pays cache latency. **Do NOT apply gfx1100's SLC/streaming cache lever here — it would
bypass the cache that's helping.** Coalesce to the 256B cacheline (sub-256B strided access wastes a full line).

## THE unused lever: FP8 / FP4 WMMA — a PREFILL lever, NOT decode
RDNA4 has **fp8 (E4M3/E5M2) + fp4 WMMA + conversion instructions.** hipfire has always gone fp16 → int8 and
NEVER used the fp8 path — "the cheaper instructions we keep believing in but haven't found the right way to
use." For mq4r (4-bit quant) the precision budget easily tolerates fp8 accumulate → potential **~2× GEMM
throughput vs fp16**.

**Scope it correctly: this is a PREFILL lever.** WMMA (and fp8-WMMA) is matrix×matrix. Prefill is
batch=prompt_length → GEMM → the 16×16 matrix cores fill up. **Decode is batch-1 → GEMV (matrix×vector); a
matrix core with M=1 wastes ~15/16 of itself, so WMMA is WORSE than a tuned dp4a/scalar GEMV on decode.** Do
NOT reach for WMMA/FP8 on the latency-bound decode GEMVs (qkvza/gate_up) — that is not the lever there
(cache-residency + the ISA int8/dp4a path are). The FP8 target is the **grouped prefill GEMM**. (The only
thing that would make FP8-WMMA a decode lever is batch-K spec-decode, which turns decode into a GEMM — parked.)
Confirm the exact `v_wmma_*_fp8` / `v_cvt_*_fp8` mnemonics from the RDNA4 ISA / LLVM AMDGPU backend.
**UNEXPLORED — arch-specific (gfx1100 has no fp8) → FORK.**

## Other compute levers
- Native WMMA (grouped GEMM already uses it, saturated — leave those). WMMA-fragment tiling for other GEMMs.
- 256B coalescing (align vector loads dwordx4/x8 to 256B).
- Improved dual-issue vs RDNA3.

## Occupancy / BW-extraction (2026-07-05): TENTATIVE — gfx1201 LESS starved than gfx1100, but STILL unsaturated
The GEMV-occupancy probe (`autoresearch/harness/gemv_occ_probe.hip`, SIMPLIFIED proxy GEMV, one shape) is
suggestive, not conclusive. Weight-read GB/s vs occupancy:
```
occ(wv/CU):     32    16     8      (DPM-WARMED + drift-checked; earlier cold table retracted)
gfx1201:       587   507   277     (of 640 DRAM = 92% .. 79% .. 43%)
gfx1100:       781   538   295     (of 960 DRAM = 81% .. 56% .. 31%)
```
At ~16 wv/CU, gfx1201 extracts ~79% of its 640, gfx1100 ~56% of its 960 — gfx1100 more occupancy-sensitive
(occ 16→32 = +45% vs gfx1201's +16%). gfx1201 nearly saturates (92% at max occ). The second bottleneck is the
1-wave-per-row access pattern (raw-load ceiling ~84% on gfx1100), partly closed by WIDE uint4/float4 loads
(→87%, arch-orthogonal — likely helps gfx1201 too; fleet test pending, except gfx1010/RDNA1).

**Tentative implication (unverified): the occupancy/VGPR lever probably helps gfx1100 more, so likely a gfx1100
fork — but since gfx1201 is also unsaturated it may help here too; measure before deciding fork-vs-shared.**
CU-scale knee ~144-192 blocks (fleet-validated: knee tracks CU count); decode grids (2k-16k) over-saturate it,
so grid is not gfx1201's limiter. gfx1201's larger headroom is likely still **FP8 prefill** (above).

## Wins / deads on record
- **v3 attention register-ring** (transferred from gfx1100): WON +2.9% → baseline_v3 (78276f03). Coherent, smaller
  than gfx1100 (attention is a smaller slice of RDNA4's decode critical path; scheduler hides more).
- **qkvza/gate_up R=2/R=3/R=4 multirow**: DEAD/regress — adds VGPR, drops occupancy.
- **NT loads on write-once weights**: PRECHECK_FAIL / no-op — gfx1201 is already cache-resident, so streaming
  the weights past cache does nothing (the OPPOSITE of gfx1100, where it's the #1 lever). Arch divergence.
